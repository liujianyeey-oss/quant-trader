# A股量化交易程序（回测 + 每日信号提醒）

基于 Python + akshare 的 A股量化研究工具，支持 ETF/个股的历史回测与每日持仓信号提醒。**不做实盘，仅供研究学习，不构成任何投资建议。**

> 建设期的全部教训（方法论/工程/运维）见 **[docs/LESSONS.md](docs/LESSONS.md)**——改代码或调参数前先读它。

## 环境要求

- macOS / Linux / Windows
- Python 3.14（本机使用 `/opt/homebrew/bin/python3` = 3.14.3 验证通过；若你的 Python 版本装不上 pandas/akshare，可改用 3.11~3.13 创建虚拟环境）
- 需要联网（数据来自东方财富公开接口，经由 akshare 访问）

## 安装

```bash
cd quant-trader
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 使用方法

### 1. 回测

```bash
# 动量轮动策略（默认，2019-01-01 至最新）
python main.py backtest --strategy momentum --start 2019-01-01

# 五组分批动量 + 波动率控仓（staggered）
python main.py backtest --strategy staggered --start 2019-01-01

# 双均线策略（单标的，默认 510300，可用 --code 指定其他）
python main.py backtest --strategy dual_ma --code 510300 --start 2019-01-01
```

回测结束会在终端打印中文绩效报表（总收益、年化、最大回撤、夏普、卡玛、交易次数、胜率，并与基准 510300 对比），并在 `reports/` 目录保存净值曲线 PNG。

### 2. 每日信号

```bash
python main.py signal --strategy momentum
python main.py signal --strategy staggered
python main.py signal --strategy dual_ma --code 510300
```

输出当前生效目标（与回测同一份信号状态、前向填充得到，不是当日重选）、目标仓位、触发原因与下次更新日期，写入 `signals/YYYY-MM-DD_<strategy>.txt`。盘中运行时会现场附加当日未完成 K 线（不写入缓存）并明确提示；正式信号请收盘后（15:30 后）查看。

### 3. 调参寻优（动量轮动）

```bash
python main.py optimize          # 网格搜索 270 组参数，打印 top 15
python main.py optimize --top 20
```

- 网格维度：`momentum_days` [10/20/30/40/60] × `rebalance_days` [5/10/20] × `trend_ma` [0(关闭)/20/60] × 防守资产 [511010/518880/空仓] × 标的池 [默认池/默认池+510880]
- 样本内 2019-01-01~2023-12-31 按**卡玛比率**排名，样本外 2024-01-01~最新做验证（防过拟合）
- 完整结果保存到 `reports/optimize_results.csv`
- 数据起点自动前移到回测起点前 ~450 天，保证长周期参数有足够的预热期
- **多重尝试风险**：270 组网格中挑样本内最优本身就有过拟合风险（参见 Bailey 等 *The Probability of Backtest Overfitting*）；用样本外表现再回头改策略会消耗留出集。当前默认参数经历过此流程，不应再被视为有真正的独立样本外证据。

### 5. 模拟盘台账（paper trading）

跟踪 momentum / staggered 两个策略各自的独立虚拟账户（初始资金各取 `backtest.initial_cash`），用于长期观察信号与实际可成交价格的偏差：

```bash
python main.py paper-update   # 每日收盘后运行：执行昨日待成交目标（今日真实开盘价），记录今日新信号与净值
python main.py paper-report   # 输出分析报表（持仓/绩效/执行偏差/理想净值对比/月度收益/最近成交），存 reports/
```

- 只用已完成日线入账（盘中运行不记录当日信号）；同一天重复运行幂等，无新交易日自动跳过
- 成交价 = 信号次日开盘价 + 滑点，费率与回测引擎同一套逻辑（先卖后买、100 股整数倍、最低佣金不透支）；开盘价缺失顺延到下一交易日
- 数据源整日不可达时当日自动跳过（降级缓存），恢复后一次运行自动补记所有遗漏交易日（逐日成交、信号、净值）；已配置 18:23 二次重试 cron 兜底
- 每笔成交记录"信号日收盘 → 实际开盘成交价"偏差（bps，含滑点与隔夜跳空）
- 存储在 `paper/`（JSON 账户状态 + CSV 流水：trades/nav/signals），纯文件可手改，文件缺失视为新账户

cron 配置（`paper/daily_update.sh` 已带绝对路径，cron 环境无用户 PATH）：

```cron
# 工作日 16:47 收盘后更新台账
47 16 * * 1-5 /Users/liujianye10/quant-trader/paper/daily_update.sh
```

### 6. 配置（config.yaml）

- `universe.etfs` / `universe.stocks`：标的池（ETF 走 `fund_etf_hist_em`，个股走 `stock_zh_a_hist`，均为前复权日线）
- `universe.defensive`：防守资产（默认 518880 黄金ETF，经网格调参选定）
- `strategy`：动量窗口、调仓周期、均线参数
- `cost`：佣金 / 印花税 / 滑点 / 最低佣金
- `backtest`：区间、初始资金

## 策略原理简述

### MomentumRotation（动量轮动，主策略）

每隔 `rebalance_days`（默认 5）个交易日，计算标的池各标的过去 `momentum_days`（默认 20）个交易日的涨跌幅（动量），持有动量最强的标的；若该标的收盘价低于其 MA60（趋势过滤，`trend_ma` 可调，0=关闭），则切换到防守资产（默认黄金ETF，可配国债ETF或空仓）。思路：强者恒强 + 趋势破位避险。默认参数经 270 组网格调参选定（样本内 2019-2023 卡玛第 1，样本外 2024+ 未掉队，见 `reports/optimize_results.csv`）；2026-09-07 已用审计修正后的引擎重跑全部 270 组，排名与旧引擎高度一致（Spearman 0.999），该配置仍为样本内第 1，结论不变。

### DualMA（双均线，对照策略）

单标的。MA5 上穿 MA20（金叉）买入，下穿（死叉）卖出。

### StaggeredMomentum（五组分批动量 + 波动率控仓，staggered）

在 momentum 的选股逻辑（20 日动量 + MA60 趋势过滤 + 黄金防守）基础上做组合层改造：

1. 5 个等权信号组（各占组合 20% 预算），分别在周一~周五收盘更新；对应星期是非交易日则该组本周跳过；
2. 每组更新时选 20 日动量最强的进攻池标的，收盘价 ≥ MA60 选它，否则选防守资产（防守资产自身不加趋势过滤，有意保留）；
3. 组内投资比例 = `min(1, vol_budget / max(σ, 0.03))`，σ = 被选资产最近 60 个日收益标准差 × √252（`vol_budget` 默认 0.12），其余为现金；
4. 每日把 5 组最后目标按 1/5 平均、按代码合并（同代码净额合并，避免对敲成本），T+1 开盘成交，不用杠杆。

效果：把单一调仓日的运气摊到 5 个交易日，并用波动率反向控仓。2024 以来（历史验证段）最大回撤从 momentum 的 -30.85% 降至 **-10.47%**（年化 18.93% vs 19.50%）；完整历史年化 14.73%（低于 momentum 的 20.58%），并非所有维度都更好。该方案是在看过本次历史结果后提出的探索性设计，2024+ 数据不能再视为其未接触过的样本外。

## 回测规则

- **T+1 执行**：当日收盘出信号，下一交易日开盘价成交；参与调仓的已有/目标持仓缺开盘价时，整次调仓延期到下一交易日重试（不用收盘价替代开盘价）
- **无前视**：开盘调仓用开盘价（而非当天收盘价）估值持仓、确定目标股数
- **信号对齐**：目标权重先合并到完整交易日历、前向填充、后移一日，再裁剪回测区间；区间前最后的已知目标会被承接
- **成本**：ETF 佣金万1，个股佣金万2.5 + 卖出印花税 0.05%，滑点 0.1%（均可配置）；现金不足按比例缩减买入，最低佣金不会导致透支
- **交易单位**：100 股整数倍
- **年化口径**：自然日年数 (末日-首日)/365.25
- **数据缓存与双源容错**：日线缓存在 `data_cache/`（parquet）；主数据源东财（`fund_etf_hist_em` / `stock_zh_a_hist`），备用数据源腾讯（`stock_zh_a_hist_tx`，ETF/个股通用，同样前复权）；东财全部镜像重试失败自动切腾讯，腾讯也失败且有本地缓存则降级用缓存（WARN 提示），缓存也没有才报错。缓存过期即按同一前复权基准全量重拉（杜绝复权接缝，东财恢复后会校准腾讯补的数据）；当日未完成 K 线不写入缓存，盘中读取自动剔除并回写（自愈）

## 修复记录（2026-09-07，依据独立审计报告）

| 问题 | 修复 |
|---|---|
| 缓存可能混入当日未完成 K 线 | 缓存只存已完成日线；盘中 signal 现场拉取当日快照不落盘并提示；盘中读取自动剔除污染行并回写 |
| 开盘调仓用当天收盘价估值/定股数（前视） | 改用开盘价估值与定股数；开盘价缺失不再用收盘价替代 |
| signal 每日重选、回测 5 天一调，两者不一致 | signal 输出改为信号前向填充后的当前生效目标，并标注下次调仓日期 |
| 前复权增量拼接可能混用复权基准（接缝） | 缓存过期即按一致基准全量重拉，不再增量拼接 |
| 信号先裁剪再前填，丢失区间前最后目标 | 先合并完整日历前向填充、后移一日，再裁剪区间 |
| 成交失败后目标不再变化时永不重试 | 待执行目标与已完成目标分离（pending 状态），未成交次日继续尝试 |
| 动量排名池用"除防守外所有列" | 显式限定为配置的攻击池（etfs + stocks） |
| 年化按交易日/252 | 改为自然日年数口径，optimize 同步 |

回归测试：`python -m unittest discover -s tests -v`（23 项：执行时点与区间前信号承接、无前视、缺开盘价延期重试、最低佣金不透支、买卖两侧成本、未来数据不改变历史信号、双源容错与缓存兜底、多日故障补记、台账幂等、未来函数专项——截断一致性/收盘篡改免疫/成交时序/逐日因果扫描/台账不可篡改）。

## 已知局限

- 数据源为东财公开接口（主）+ 腾讯（备用），盘中数据可能有延迟；个别网络环境下东财接口会间歇性断连甚至整段封禁，程序内置镜像轮询重试 + 腾讯备用源自动切换 + 缓存兜底三级容错。腾讯源与东财 qfq 口径已逐日核对一致；若腾讯补齐期间发生分红除权，两家复权因子可能有细微差异，东财恢复后的全量重拉会自动校准。
- akshare 接口可能随版本改名，本代码基于 akshare 1.18.94 验证。
- 前复权价格会随除权除息整体重算；缓存已按一致基准全量刷新，但前复权价做 100 份取整只是研究近似，不等于历史真实成交股数。
- 未模拟涨跌停无法成交、真实开盘深度、成交量参与率；现金收益按 0 计。
- staggered 是看过历史结果后设计的探索性方案，其数字不构成独立样本外证据；动量类参数（20 日动量等）本身也经过寻优，存在残余过拟合风险。
- 2026-09-07 之前的缓存曾混入当日盘中数据，新版数据层已能在运行时自愈（剔除并回写）。

## 项目结构

```
quant-trader/
├── config.yaml      # 标的池 / 策略参数 / 交易成本 / 回测区间
├── data.py          # akshare 数据拉取 + parquet 缓存
├── strategies.py    # 策略基类 + 动量轮动 / 双均线 / 五组分批动量(staggered)
├── backtest.py      # 回测引擎（T+1、开盘价成交无前视、延期重试、100股整数倍）
├── metrics.py       # 绩效指标（自然日年化）、中文报表、净值曲线绘图
├── main.py          # CLI（backtest / signal / optimize）
├── optimize.py      # 动量轮动网格调参（样本内/样本外）
├── paper.py         # 模拟盘台账（每日更新 + 分析报表 + 执行偏差统计）
├── tests/           # 回归测试（执行时点/成本/信号因果性/台账）
├── data_cache/      # 日线数据缓存（自动创建）
├── paper/           # 模拟盘台账（account/trades/nav/signals + daily_update.sh）
├── reports/         # 净值曲线 PNG（自动创建）
└── signals/         # 每日信号文件（自动创建）
```
