# OC1：BTC 链上数据策略 sprint（终判）

日期：2026-09-17。判定口径：生产引擎（T+1 开盘 + taker/滑点，research_r4 公用函数），基线 = BTC donchian 20/10 + F1。纪律：train ≤2022-12-30 判效（卡玛改善 ≥0.1）、valid 2023-2024 体检、2025+ 只报告。

| 指标 | 行数 | 覆盖 | 用途 |

## 判定

| 假设 | 结果 | 判定 |
|---|---|---|
| **O1 交易所抛压阻塞** | 免费源无 exchange flow 数据 | **不可测**（不伪造） |
| **O2 价/活背离降权** | train 卡玛 **1.47 vs 基线 1.92**（阻塞 412 天，train 恶化 0.45）→ 违反判效线；valid 4.40 优于基线 3.19 但按纪律训练段定生死 | **证伪**：拦掉的"弱反弹"-entry 恰是利润来源之一；链上活跃度背离在短窗（20日动量）上是滞后指标而非预警 |
| **O3 哈希带宽** | 当前哈希率回撤 **-17.9%**（阈值 -30%）→ 正常区间 | 持续输出指标（纳入周状态），不参与交易判定 |

## 结论

**账户 5 不加链上否决开关。** 与此前所有过滤器的统一死法一致：任何"在入场前再多问一个问题"的机制，在我们的样本里拦下的好交易多于坏交易。链上数据的正确用法在本体系内是**周期状态展示**（O3 哈希带宽这类慢变量做报告，不做信号），不是交易否决。

数据的剩余价值：AdrActCnt、TxCnt、hash_rate 已入缓存并纳入每周 monitor 的状态面板（慢变量，不含信号）。
