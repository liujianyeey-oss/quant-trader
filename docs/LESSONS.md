# 经验记录（Lessons Learned）

> 2026-09-07 ~ 09-08 建设期的全部教训与结论。新成员/新会话先读这份文件再改代码。

## 一、量化方法论教训（最值钱的部分）

1. **单次回测高收益可能是相位运气**。旧 momentum 参数（5 日调仓）曾报出 +60% 收益，加信号预热期后同一参数是 -4.3%——单标的 5 日调仓对"周几调仓"极度敏感，5 个相位中 4 亏 1 赚。**教训：任何调仓周期 > 1 日的策略，必须做相位扰动测试（或像 staggered 一样把五个星期几分组全纳入），否则收益数字不可信。**
2. **网格寻优的 top 组合会奖励运气成分**。270 组寻优的榜单头部全部选择了黄金ETF 防守，本质是奖励"恰好押中 2024 后黄金大涨"的组合。防守资产选择本身就是选模自由度。**结论：选参看"高原"（邻域组合全部为正）不选"孤峰"；样本外只作体检不作选参依据。**
3. **样本内/外切分只能用一次**。看过 OOS 结果再改策略，留出集就被消耗了。2024+ 数据对本项目已不再是独立样本外。换参纪律：只按样本内（2019-2023）排名决策。
4. **多重尝试风险是真实的**（Bailey et al., The Probability of Backtest Overfitting）。270 组里挑卡玛最高者，即使无前视也可能过拟合。本项目未做 PBO 估计，对任何回测收益保持折扣心态。
5. **趋势过滤和防守资产是策略最大的 alpha 来源**。分组统计：trend_ma=60 的 IS 卡玛均值 0.122 vs 关闭过滤 0.064；黄金防守 0.152 vs 国债 0.041。选什么"躲"比选什么"攻"影响更大。

## 二、工程质量教训（Bug 编年史）

| Bug | 教训 |
|---|---|
| 回测用当日收盘价估值来定开盘成交股数（前视） | **执行价和估值价必须同源同时刻**；开盘成交就只能用开盘价 |
| `signal` 每日重选冠军，回测 5 天一调，两者 342 天不一致 | 信号输出必须来自与回测**同一份目标持仓状态**，禁止两套逻辑 |
| 盘中快照按日期缓存后不再刷新，残缺 K 线永久留存 | 缓存只写已完成日线（`date < today`），盘中数据只进内存 |
| 收盘后全量重拉误删当日已完成 K 线 | "剔除当日行"的逻辑必须区分盘中/收盘后；此 bug 导致 cron 永远看不到当天信号 |
| 前复权数据增量拼接会混用复权基准（分红后接缝） | qfq 缓存更新只能全量重拉，不能拼尾巴 |
| 成交失败后更新 prev_target 导致订单永不重试 | 待执行状态与已完成状态必须分离 |
| 信号先裁剪区间再前填，丢失区间前最后目标 | 先并日历 → ffill → shift(1) → 再裁剪 |
| 持仓标的单日缺行情（159915 缺 2021-02-08）导致估值归零、回撤 -99.98% 假指标 | 估值价前向填充；**对离谱指标保持怀疑，-99.98% 一定是数据问题不是策略问题** |
| pandas 3 下 `Series[-1]` 语义变化 | 时间序列索引用 `.iloc[-1]`，升级依赖后跑全量测试 |

**未来函数审计（2026-09-08）**：五环节逐行审查 + 7 项专项测试（截断一致性/收盘篡改免疫/成交时序/逐日因果扫描/台账不可篡改）全部通过，共 23 项测试。结论：因果链干净。改任何执行/信号代码后必须重跑 `python -m unittest discover -s tests`。

## 三、数据源与运维教训

1. **免费公开接口会被风控**。东财对本机 IP 封禁（2026-09-07，curl/python 全镜像 000，其他网站正常），诱因是短时间内高频全量重拉。任何依赖单一免费接口的系统都必须有备用源。
2. **双源容错体系**（data.py）：东财（主）→ 腾讯（备，qfq 口径一致，当日数据收盘后约 2 小时产出）→ 本地缓存（兜底，不崩溃）。新浪准确性 OK 但当日晚才更新，只配做三备。
3. **cron 设计**：主运行 16:47 + 兜底 18:23（工作日）。幂等 + 逐日补记机制保证漏跑、重跑、连续故障恢复后都正确。腾讯源当日数据晚产出时，16:47 可能记前一日，18:23 兜底正好补上。
4. **macOS cron 在机器睡眠/关机时不执行**——靠"无新交易日自动跳过 + 恢复后补记"兜住，无需告警，但周报时应检查 nav 最后日期。
5. **macOS 通知的坑**：`osascript display notification` 返回 0 但通知可能根本不显示（归属"脚本编辑器"，权限/路由问题静默失败，实测三次均不可见）；`terminal-notifier` 在 iTerm 下报 "Notifications are not allowed for this application"（责任进程归属问题，重置 TCC 无效）。**验证通知链路必须用模态弹窗（display alert）实测**，不能只信退出码。最终方案：terminal-notifier 优先、模态弹窗兜底（paper/notify_signal_change.py）。
6. **台账设计**：纯文件（JSON+CSV）、幂等、可手改。成交复用回测引擎同一套 `_rebalance`，保证台账与回测口径天然一致。

## 四、回测 ≠ 实盘的结构性偏差（非未来函数）

| 偏差 | 方向 | 处理 |
|---|---|---|
| 滑点固定 0.1% | 未知 | 用台账 dev_bps 累积数据校准（2026-09 起） |
| 现金收益按 0 计 | 低估 staggered（常年 37~46% 现金）约 1.5% 年化 | 知悉即可，实盘买货基/逆回购 |
| ETF 分红现金未入账 | 低估实盘（红利ETF 年年分红） | 知悉；台账不含分红现金流 |
| 涨跌停/停牌未模拟 | 纯 ETF 池影响极小 | 缺开盘价延期重试已兜底 |
| qfq 价 100 份取整近似 | 100 万资金下 <0.5% | 资金越小失真越大，10 万以下谨慎外推 |
| qfq 因子含未来分红信息 | 比率型信号（动量/均线）不受影响 | 绝对价格会变，收益率不变 |
